# 情绪由客户自报增量，而非导演独立评估

为 1v1 训练新增情绪压力引擎时，我们决定：情绪状态的唯一来源是客户 agent 每轮随回复输出的结构化 `emotionDelta`（数值 + 原因），由本地状态机夹紧在 0–100；不引入导演（director）每轮独立评估情绪的额外 LLM 调用。

**理由**：比赛演示对延迟敏感，每轮多一次导演评估调用会拖慢对话节奏；夹紧规则足以兜底短期漂移。导演校准作为发现漂移后的升级路径保留，不在首版实现。

**同时决定**：难度（easy/medium/hard）不再携带静态情绪人设文案，而是参数化为「初始情绪值 + 敏感系数」，由引擎统一放大 emotionDelta——避免两套情绪逻辑并存。

**Considered Options**：导演每 N 轮独立评估校准（更准，但每轮多一次调用，演示延迟不可接受）；关键词规则驱动（延迟最低，但评委试探两句即可摸到规律，演示效果机械）。

**Consequences**：情绪曲线质量依赖客户 prompt 中 emotionDelta 的输出约束，需要回归 prompt 时一并验证增量输出的稳定性；复盘页的转折点归因直接消费 delta 自带的「原因」字段。
